ACID, using a bank transfer

ACID describes four guarantees for database transactions. A $40 transfer makes the differences easier to see. 1

DatabasesTransactions

1Four guarantees

Both changes happen together

Moving $40 between two accounts needs two updates. A transaction makes the debit and credit one unit. 1

  1. Begin the transfer

    Start a transaction before changing either balance.

  2. Make both updates

    Debit the sender and credit the recipient.

  3. Commit or roll back

    If either update fails, keep both original balances.

Keep the database rules true

A committed transaction must respect declared constraints, such as unique account IDs and valid account references. 1

A rule you define

If negative balances are forbidden, a CHECK constraint can reject an update that breaks that rule.

Control what concurrent work can see

Transactions can overlap. The isolation level controls which intermediate changes and concurrency effects they can observe. 2

Isolation levels matter

Serializable has stronger guarantees than read committed.

Keep a committed transfer

After the database confirms a commit, it must preserve that result through a crash under its durability guarantees. 2

After commit

The transfer should still exist when the database restarts.

A database can enforce declared constraints. It cannot detect every mistake in your application logic. 1

Questions to the user

Capy can ask questions before or inside a reply, for any task: here it gathers context before writing a note. The questions live in one block that stands apart from the answer text and sits by the composer. Picking an option moves to the next question, Something else takes a typed answer, Skip leaves one out, and one Send posts every answer as one ordinary message. The composer keeps working beside it. The block belongs to the latest reply only: once any message is sent, unanswered questions stay readable in the history and are never asked again. Reloading clears unsent answers. Keys 1 to 3 pick an option in D and E.

I recommend E. It never covers the answer, needs no overlay or scroll padding, and still sits right above the input. D is the floating block; it needs Hide so the end of the answer stays reachable. F keeps the questions in reading order but away from the input.
