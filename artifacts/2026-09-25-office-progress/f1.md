## Choices the developer should confirm

1. PPTX went straight to the F3 seeding design during the merge (deck.rs, lib.rs): schema 5.0,
   no packageJson or media in Yjs, source required to open. DOCX F3 was not done (seed.rs had
   no conflict).
2. Upstream's proposal store, search API and their WASM exports are kept as source (merged, not
   wired into Capy). Deleting them would add modify/delete conflicts on every sync.
3. SourceImport pass modules (`effects.rs`, `outline_gradients.rs`, `source_run_properties.rs`)
   and the comment/numbering/render import functions were deleted (record 10), not kept dormant.
4. Upstream's `hydrate_local_doc` (lenient decoder for engine-produced bytes) is used for
   staging and the canonical rebuild, as the handoff table says; the review calls it unneeded.
5. XLSX preserved row/column markup is off in schema 7 sessions (stopgap), so edited sheets
   reserialize row and column markup.
6. Array formulas in schema 7 survive only while the anchor cell's stored content equals what
   bootstrap seeded; `retain_formula_caches` stays address-based.
7. `XlsxEditor` `onChange` now fires only when a result is applied (upstream semantics); Capy
   does not use `onChange`.
8. The PPTX remote-metadata check compares all of `pptx:meta` except `commentFlavor` on every
   remote update (cost grows with a rebase overlay's size).
