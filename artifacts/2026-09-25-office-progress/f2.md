## What each item does

- **F2.1 fonts, engine side.** `DocxViewDocument` opens in steps: `open` (parse, seed),
  `layoutRequestJson`, `fontRequirementsJson(request)`, `layout(request)` (keeps only the display
  list). `openDocumentViewer` registers the required faces through `createRustMeasureSource` on the
  viewer module's own font store (`viewTextEngine` in `packages/docx/src/wasm/viewer.ts`) with the
  provider `configureDefaultFonts` sets, which the viewer entry now re-exports so the worker can
  configure fonts without importing the editor. The Rust request now matches
  `buildResidentRegionLayoutRequest`: resolved final section with its id, section ids from
  properties, TOC style ids, default paragraph style. Tests (`packages/docx/src/wasm/viewer.test.ts`):
  request parity on `feature-rich.docx` and a two-section package with a footnote and TOC styles by id
  and by name; with a configured provider the fixture lays out more lines than without. Viewer WASM
  7,436,957 -> 7,452,666 bytes (+15.7 KB), still 74.7% of the editor.
- **F2.2 replace_text** (`shared/office-checkpoint.ts`). A surrogate-safe common prefix and suffix
  give the changed span. DOCX calls `replaceRange` on it and treats tracked insertions like tracked
  deletions (not offered by inspect, refused by apply). PPTX deletes and inserts only the span with
  the style of the run holding the first replaced character, and builds `paragraphId -> storyId` once
  per call. Tests: bold "cats" -> "dogs" stays bold with plain neighbours, a tracked-insertion
  paragraph is refused; a PPTX "Plain Bold" paragraph keeps its plain and bold runs through two
  commands. Both failed on the old code.
- **F2.3 XLSX.** `float_roundtrip` and `canonical_cell_formats_preserve_high_precision_theme_tints`
  came with the merge (`e8c4f5b3`). The single-materialize patch was adapted (upstream `775f184f`
  already returns the staged model): `stable::apply` materializes once and carries each op's model
  forward; the facade passes the staged structure to `install_model_with` for user and agent commits.
  The review's three-op test (`stable_collaboration.rs`) wrote italic instead of bold before.
- **F2.4 DOCX opaque drawings** (record 14). The parser keeps a `w:pict`, `w:object` or
  `mc:AlternateContent` it cannot model as `OpaqueDrawing` (raw XML, `r:id`s included) instead of
  dropping it; an AlternateContent holding a text box still becomes the modeled text box. Both seeders
  store an `opaqueDrawing` embed `{kind, xml}`; the layout reserves its position and draws nothing;
  the projection returns the run and the serializer replays it (upstream `4bf205b5`). Fixtures added
  to the fork: `poc/fixtures/exchange-plan.docx` (Capy rich-content) and
  `poc/fixtures/opaque-objects.docx` (generated by calling only `opaque_docx` of
  `probes/storage/gen_files.py` with `random.Random(20260925)`, so its random text differs from a
  full-script run). The checkpoint test seeds, edits and exports each file twice and checks chart
  `r:id`s, their relationships and the VML rectangle. The merged engine already kept both charts of
  `exchange-plan.docx`; capy-ci dropped them.
- **Choice 1 decision** (record 14, `d1a2972b`). A picture or shape the parser reads from
  `w:pict`, `w:object` or `mc:AlternateContent` carries that element's raw XML as `sourceXml` on
  its run content item (not in the Image or Shape model, so `shapeJson` and seeder parity are
  untouched). Both seeders copy it into the embed payload; the projection passes it back; the
  serializer replays it instead of the model. `set_embed_attrs`, `set_embed_attrs_by_id` and raw
  `setEmbedAttr` drop `sourceXml` when any other payload entry changes value, so an edited object
  saves as its model (an edited text box as DrawingML without the VML fallback, an edited OLE object
  as its picture); rewriting an unchanged value (the rebase's `rId` rebinding) keeps it. An
  AlternateContent whose chosen branch holds more than one drawing gets no `sourceXml`. Test

  exports byte-equal with `rIdOle` still in the relationships and both AlternateContent text boxes
  export byte-equal; resizing one text box saves it as DrawingML (one AlternateContent left, two
  `wps:txbx`).
- **F2.5 PPTX comments** (record 15). Seed, snapshot and save already carried comments, and remote

## Choices to confirm

1. **Decided** (record 14, implemented in `d1a2972b`): displayable objects export their authored
   XML until edited. New consequence to confirm: upstream's native `Document::save` (not used by
   Capy) replays unedited objects the same way, because the serializer replays `sourceXml` whenever
   present and the native API cannot edit pictures or text boxes. Upstream's
   `saving_keeps_shape_text_box_bodies_and_character_unit_indents` now expects the AlternateContent's
   VML fallback kept (three `w:txbxContent` instead of two); that one assertion was changed. The
   alternative is gating the replay to the Yjs export path, which needs a flag through the native
   parse.
2. **F2.4, raw drawings draw nothing.** A VML shape kept as raw XML occupies one position and paints
   nothing in the editor and viewer. Before, it was dropped, so this is no regression.
3. **F2.2, edge rules.** A PPTX pure insertion (nothing replaced) takes the style of the character
   before it, like the DOCX engine's collapsed `replaceRange`; a replacement equal to the current
   text changes nothing; DOCX paragraphs with tracked insertions are hidden from `inspect` as well as
   refused (as tracked deletions already were).
4. **F2.1, fonts.** The viewer uses bundled faces only; fonts embedded in the document are not fed
   to it (it has no TS parse). A face that fails to load still falls back silently inside the font
   registry; the explicit error of record 16 is left to Capy's provider in C5. `contractVersion` and
   `regions.watermark` are absent on both sides of the parity test because parsed packages carry
   neither.
5. **Confirmed** by the developer: PPTX comment changes produce no pending effects (Capy's
   `pptxEntries` has no comment entries); only comment slide ids are remapped in the indexed state.
6. **F2.6, root list source.** `OFFICE_DOCUMENT_ROOTS` is a TS constant mirroring the engines'
   root names (the fork has no `yjs` to test it against seeded states). C5's service tests should
   assert that every seeded fixture's roots are inside it. `xlsx:rebase` goes away in F3 (schema 8).
