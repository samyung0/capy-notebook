## Root cause shared by every failure

The `e2e_check` job installs Bun, Rust, `wasm-pack` and restores the BetterOffice
WASM cache, but it never runs `pnpm office:prepare`. Both Playwright configs start
`pnpm exec vite` directly, so no `pre*` script runs either (`predev` was removed in
`57f8ad25`, and Vite never ran through it anyway). As a result,
`vendor/betteroffice/packages/docx-react/dist/styles.css` does not exist on the runner.
`src/office-runtime/main.tsx` has imported it since `56a398c5`.

Nothing in CI opened the Office runtime until `729618db` (frontend part 37,
2026-09-23) added the Office editor specs. Since then, whenever a spec loads the
runtime iframe, Vite logs:

> `[vite] Internal server error: Failed to resolve import "../../vendor/betteroffice/packages/docx-react/dist/styles.css" from "src/office-runtime/main.tsx". Does the file exist?`

Vite sends that error to every connected page, and `<vite-error-overlay>` then
covers every page open at that moment. The Office specs fail because the runtime
never loads. Specs running beside them in the other worker fail because the overlay
blocks their clicks:

> `<vite-error-overlay></vite-error-overlay> intercepts pointer events`

The editor project never ran to completion in CI before this, because earlier jobs
failed in the `chromium` project first (for example, run 35873810512 at `729618db`
stopped on the Add file locator). So this never showed up.

No failure was a stale test or a product regression. With the Office assets built,
every listed spec passes against the current code. I checked the Office records in
`human/frontend/office-files.md`: the handoff banner, the quiet `source-publishing`
auth retry, store-only export-only publication and the maintenance pause. Also
`human/frontend/plate-editor.md` and `human/frontend/error-handling.md`. None of these
specs contradicts them, so neither side needed a decision.
