Mermaid blocks with modern_mermaid themes

Every diagram here is real output from our installed mermaid 11.16 with six presets taken from modern_mermaid: Linear Light, Linear Dark, Brutalist, Material, Hand Drawn and Kawaii. The grey bordered box is gone. Each diagram sits on its theme's own background with no border, so white themes look frameless. Editing uses option D from the last round.

What modern_mermaid actually is

  • It is an editor web app, not a library, and it isn't on npm. Its themes are plain mermaid.js configs (theme: 'base', themeVariables, themeCSS). We keep mermaid.js and copy the six presets in as data (MIT, with attribution). Every diagram type keeps working, including mindmap, pie, gantt and timeline.
  • Hand Drawn adds two SVG "roughen" filters after rendering and uses Excalifont (OFL, 52 KB woff2, self-hosted). Excalifont has Latin glyphs only, so Chinese labels fall back to the system handwriting font.
  • Kawaii uses Comic Sans MS, which Mac and Windows have and Android and ChromeOS don't. Material asks for Roboto, which we don't load, so it falls back to our sans.
  • Theme CSS is 1 to 15 KB per preset and goes into each diagram's SVG. Mermaid scopes it to that SVG, so blocks with different themes on one page don't clash.
  • mermaid.initialize is global. Blocks with different themes rendering at the same moment could pick up each other's theme, so renders go through one queue: set the theme, render, then the next block.
  • The theme is stored per block as an optional theme field on the mermaid node. The server and collab validators ignore extra fields, so it's additive with no migration. Blocks without it use the default theme.

The six presets

A flowchart with a decision and the cell mindmap in each theme.

Linear Light

White nodes, hairline grey borders. The quietest option; a good default.

Linear Dark

Zinc nodes on near-black. Needs its dark panel on a light page.

Brutalist

Beige panel, black borders, hard offset shadows, yellow and orange accents.

Material

White cards with soft elevation shadows. Font is Roboto, which we do not load yet.

Hand Drawn

Excalifont lettering and a roughened stroke filter on paper-white.

Kawaii Cute

Pink panel, rounded pastel nodes, Comic Sans lettering.

In a note

The theme switcher is the first item on the block's toolbar: a dropdown showing the current theme's swatch and name. Picking a theme redraws the block right away and saves it for everyone. The toolbar appears in edit mode only.

Click crash fix (unchanged from last round)

  • The mermaid node is void but its only child is a mermaid_caption element. slate-react maps the click's DOM selection to that element instead of a text leaf, and marks() and the Yjs cursor sync throw.
  • Fix: make the block non-void, keep the diagram contentEditable=false, and edit the caption inline under it as in the mock above. The stored shape doesn't change.

Decisions

  1. Linear Light and Linear Dark: two separate entries (as shown), or one "Linear" entry that follows the app's light or dark mode? One entry avoids a black panel in a light note.
  2. Default theme for new and existing blocks: Linear Light?
  3. Theme background: keep each theme's panel colour (Brutalist beige, Kawaii pink, Hand Drawn paper), or draw every theme on the note's background?
  4. Material: load Roboto for it, or let it use our sans?
  5. Should the theme dropdown also appear in the edit dialog, or stay on the toolbar only?
  6. Exports and chat: exports render with the block's theme. Chat still shows Mermaid as plain code; leave that for later?
