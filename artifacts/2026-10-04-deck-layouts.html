Deck designs, round 4: ppt-master's own method

The deck tools now work the way ppt-master does: the model writes every slide as an SVG, ppt-master's checker refuses a slide whose text leaves its box or whose boxes overlap, and ppt-master's exporter turns the slides into native, editable PowerPoint shapes. The model is GLM-5.3-Flash at high reasoning, the production chat default. Images are the exported .pptx files rendered by LibreOffice.

A deck the agent built

GLM-5.3-Flash at high reasoning on the playground's lab target, asked for a short lecture deck on tangents with Library on. It searched and read Euclid's Elements Redux, captured three figure pages, outlined nine slides and wrote them one per call; the checker sent one slide back for overlapping boxes, and the Sources slide comes from the deck's provenance. 12.8 minutes, about 944k input and 43k output tokens; ten writes were refused for missing ledger fields, which the next run avoids.

How it works

  • create_deck: an outline, one title and brief per slide (what the student knows before and after, how the points relate, the content and its source). The result carries the style: palette, type sizes, page chrome and three reference slides.
  • write_slide: one slide as SVG per call. ppt-master's checker runs on it; a refusal comes back with the checker's message and the model resends the slide.
  • Once every slide is written, a Sources slide is added from the deck's provenance and the deck is exported.
  • More styles are folders of a style sheet, reference slides and a Sources template; templates with Masters and slots come later. The adoption guide is lab/playground/DECKS.md.

Not in this round

  • Native charts and tables; charts are drawn as shapes.
  • The app's PPTX viewer serves only Arial (Liberation Sans), so Cambria titles fall back there until Caladea is loaded; PowerPoint shows them as designed.
  • Style choice and user styling preferences (Later in todo-learning.md).
