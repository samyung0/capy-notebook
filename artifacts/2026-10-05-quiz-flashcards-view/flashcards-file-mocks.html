Images

Card images follow quiz images

  • One image per card, on the front under the text.
  • 2 MB, checked in the browser and on the server. The browser shrinks a larger image first (long side 2000 px, WebP, JPEG where WebP can’t be encoded, PNG for transparency, animated GIFs refused).
  • The picked image stays in the browser and uploads when the card is saved. An abandoned pick never reaches storage, and a failed upload fails the save.
  • The card stores only the asset id. The file sits in the private bucket, and every view asks the server for a short-lived signed link after an access check. Signed-out share pages go through the share token, as shared quizzes do.
  • Images belong to their set: trashing the set trashes them, purging deletes them, and an image removed from a card is deleted on save.
  • Changing an image keeps the card’s review progress.

Images

How quiz images work today

Card images would reuse the quiz image path: the browser uploads straight to storage, the server checks the file, and readers get a short-lived link.

Size20 MiB per image, enforced by the server. It checks the declared size when the upload starts and the real size when it finishes, and rejects a mismatch. There is no check in the browser, so an oversized file fails only after it has uploaded.
TypesPNG, JPEG, GIF, WebP and AVIF, checked by extension and by the file's first bytes. The quiz picker offers SVG, which the server always rejects, and doesn't offer AVIF.
DimensionsUp to 10,000 px a side, checked only when the question is saved, after the upload is already charged.
Who paysThe workspace owner for a workspace quiz, the quiz owner for a standalone one. An image removed from a question stays charged until the quiz or workspace is deleted.
CopiesCloning copies the images that are still referenced and charges the person cloning.
Signed-out linksShared quiz pages serve their images. The site currently answers 404 for any image on a shared flashcards page.
