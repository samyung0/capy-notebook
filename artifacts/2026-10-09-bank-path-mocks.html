Question bank landing, round 6: budgeted biomes, drawn on demand

Same biome map as round 4, now with density labels, a hard element budget, seeds that keep a topic's map stable, and only the visible stretch drawn.

Density labels are measured

  • Every element has a visual weight: its size times how much of it is ink or coloured fill. A round tree or a sheep is heavy, a grass tuft is almost nothing. Water and crop fields count 1.6 times, because coloured fill reads heavier than line drawing.
  • Each biome is generated on its own from 30 seeds and its average weight per question-width decides the label: under 6 is sparse, 6 to 11.5 medium, above that dense.
  • Sparse: meadow, hills. Medium: lake, river, village, farm. Dense: forest, camp. The gallery page has the numbers.
  • Village now has a house every 2 to 3 questions through the whole stretch (plus the cabin pair and well in the middle), so it reads the same everywhere, not just around one cluster.

Rhythm

  • No two dense biomes side by side, never three sparse ones in a row, and a dense biome at least every fourth biome. Checked over 300 random topics: no breaks, at most 3 biomes between dense ones.

Budget

  • Each biome has its own fill (how many elements per question-width it aims for). On top, every question-width has two ceilings for all biomes: 5 elements (grass, pebbles, flowers and butterflies count half) and a visual weight of 22.
  • Landmarks (windmill, cabins, lake, tent) use up the budget of the stretch they sit in.
  • Result: the busiest desktop view of the 34-question map holds 67 elements. The whole 34-question map is 143; a 20-question map is 85.

Only what's on screen gets drawn

  • Every piece of scenery (each element, each short stretch of horizon, each lake, field or river) knows its left and right edge. A map view draws only pieces that overlap the visible stretch plus a 120-unit margin, and updates as you scroll, at most once per frame.
  • The faint copy only holds pieces past the cut-off point and the full-ink copy only pieces before it, so nothing is drawn twice.
  • The example maps below show a live count. "Pieces" includes horizon segments and shading, so it is higher than the element count above. Scroll a map sideways and watch it change.
  • In the app this is a filter on the piece list, so off-screen pieces are not rendered at all. The visible range is rounded to whole question-widths, so React re-renders once per 60 units scrolled, not on every scroll event.

Seeds

  • Yes: the topic id is the seed. Same topic, same map on every visit and device; different topics get different maps (compare the 20-question one below).
  • Each part of the map has its own seed stream (biome order, each landmark, each question-width of scatter, sky, horizon), so adding questions to a topic leaves everything already drawn in place and only extends the end. Checked: a 34-question and a 40-question version of the same topic match exactly up to question 33; only the summit end moves.
