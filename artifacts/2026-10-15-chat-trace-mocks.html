Chat activity: tool calls and thinking

Rows follow shadcn's Trace: an icon, a sentence that says what happened, optional muted detail, and a chevron when the row expands. Each kind of work has its own icon, and while the step runs the icon acts it out: a pen writes, a magnifying glass searches, a page turns, an hourglass runs while the model thinks. When the step finishes the same drawing stops moving, so nothing swaps. The newest tool without an outcome is the running one, so nothing new is needed from the backend.

  • Titles are present tense while running (“Searching…”), past tense when done (“Searched…”), and say “Couldn't…” on failure.
  • Icons are 18px, the app's icon floor, on a 24-unit grid with a 1.6 stroke. Chat rail drawn at 400–480px wide, the rail's minimum.
  • Motion follows ldrs: holds at the ends of a move, ease-in-out between, ease-out going up and ease-in coming down, linear for anything that flows, a squash on landing.
  • Reduced motion stops the icons and the shimmer; the title still says what is happening.

Questions before building

  1. Pick L1 or L2 for running titles, and muted or accent running icons.
  2. Decided. Settings → Customizations gets a Chat section with Steps: Normal (default, one live row that folds into a summary) or Verbose (every step stays), saved with the account. The in-between layout is dropped.
  3. Redo needs no IndexedDB. An Undo already runs through the same engine as an edit and gets back its own inverse and guards (undo_material_commands returns them), which today are thrown away. Keeping them in agent_edit_inverses under the Undo's operation id makes the Undo itself undoable, and that is Redo: same endpoint, same guards, any number of times. A browser copy would miss other tabs and devices, and the server would have to trust edit commands sent from the browser.
  4. Decided. A refused Undo or Redo shows an error toast (“Couldn't undo the edit” and why) and disables the button. Trash, a source rebuild or compaction end Undo for good; the button shows disabled after reload. On a created file, Undo moves it to trash and Redo brings it back.
  5. Durations (“Thought for 3s”, “Worked for 14s”) need a start and end time per block. The browser can time a live turn, but reloaded history has none unless the stream stores timestamps. Drop durations, or store them?
  6. Reasoning text is not streamed today, so Thinking rows do not expand. Keep them as plain rows?
  7. Tool details carry ids, not names (read_document sends a file id). The rows need titles: resolve them from the workspace files list in the browser, or send the title in the tool event?
  8. Result counts (“6 results”, “8 questions”) are not in the tool_end event yet. Add a short count to the outcome, or leave rows without counts?
  9. read_skill is internal. Hide it, or show it as “Checked how to build decks”?
