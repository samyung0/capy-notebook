Study progress: a page of its own

Mock round 2, 18 Oct 2026. Biology 101 data. Nothing implemented.

Round 2 fixes, checked against the code and recorded decisions: scores are plain "x / y" and recall is a word, with no percentages anywhere (Learning's 10 Oct rule, Study tab's "no percentage"); every quiz and set sits in its one tree chapter, as review groups do, so no quiz is shared between chapters; files are only done or untouched (nothing records opening a file), so Mendelian genetics.pdf is "not read yet"; the weak-items button opens the existing whole-workspace review instead of a new item-list session; the attempts filter is workspaceId.

The workspace Study tab stays the quick view: next item, suggestion, four cards, per-chapter done counts. This page is the long version: coverage, chapters, files, quizzes and cards in one place, plus what to review. Below are three shapes with the same data, a desktop and a phone rendering of each, then the decisions I need before code.

1. What the page can show, and what each block costs

Checked against the running API and the tables behind it. today means the data already reaches the browser. partial means the data exists but one part is missing. new means server work.

BlockSource todayCost
Coverage: done, started, untouched per item and per chapter GET /api/workspaces/{id}/study plus the chapter, file and material lists. The Study tab already derives this in the browser. today
Workspace map with a stop per item GET /api/learning/progress?lead={id} returns the leading workspace's items. Built already for Learning. today, but it is a global endpoint capped at 10 workspaces
Next action: Continue and the workspace suggestion StudySummary.suggestion, and the unfinished sessions in GET /api/review/overview today
Quiz attempts for this workspace GET /api/attempts?workspaceId=, 30 a page, each with score, date, quiz name, chapter names today
Review sessions for this workspace GET /api/review/sessions?workspaceId=, with quiz marks, cards remembered, answered of total today
Per set: cards rated of the set's cards, rating mix, last studied Tables only: review_states, review_log, flashcard_cards, and the set's current cards for the total new aggregate
Recall per item, set and chapter (solid, shaky, fading) review_states stability and last review, through review.Retrievability in Go. Nothing computes it per item today. new aggregate
Weak items with the prompt or card front, misses and last rating review_states and review_log joined to the parsed document items (itemsOf) new endpoint
Time studied A session's started_at to last_answer_at. Attempts carry no duration, and reading a file records nothing but its latest change. partial: review sessions only
Activity by day, streaks Timestamps exist in review_log, attempts and review_sessions. Reading activity is not recorded. new query, incomplete picture

Constraints the design has to live with:

  • No schedule. Signed-in users see no due date, due count or interval preview (decision of 9 Oct). Memory shows up as recall, never as "due tomorrow".
  • Embedded quizzes and sets record nothing, so they never appear here.
  • Every number is the signed-in user's own. There is no class or teacher view.
  • Chapter names are snapshotted into attempts. Renaming a chapter breaks a name join, which is why the mock keeps quiz scores on the quiz, not averaged per chapter.
  • Marking a file read keeps one timestamp that the next mark overwrites, so "read on" is the last change, not a history.

Recommendation: ship one new endpoint, GET /api/workspaces/{id}/study/progress, returning chapter and material rollups plus the weak items. Coverage, attempts, sessions, Continue and the suggestion come from endpoints that already exist, so the endpoint stays small.

A Report

Coverage and chapters first, practice second, history last. Densest of the three, and the one that reads like a term report: you can answer "how much, how well, what is left" without scrolling past coaching copy.

  • Map with Continue
  • Four totals
  • Chapter table: done, practised, recall, last studied
  • Flashcards and quizzes side by side
  • Three items to look at again
  • Recent review sessions

2. Decisions I need before code

My recommendation is in each line; say "all as proposed" if they all read right.

  1. Shape. A, B or C, or a mix of their blocks. Recommendation: B's opening blocks on A's body (do next, look at again, chapter table, practice, recent), since the weak items are the reason to leave the Study tab at all.
  2. Scope and URL. One workspace per page at /workspaces/{id}/study, not a global study page. Recommendation: yes, and make it the phone Study page, which the workspace does not have below lg today.
  3. Entry points. A "Progress" link in the Study tab's tab row, the workspace header's menu, and Learning's Progress rows. Recommendation: the Study tab row plus Learning's rows; no extra header button.
  4. Blocks to ship. Coverage per chapter, map, Continue, suggested review and unfinished session, chapter practice and recall, per-set and per-quiz numbers, weak items, recent sessions. Recommendation: all of them, with the map only when it fits (desktop), a compact trail on phones.
  5. New server work. One endpoint, GET /api/workspaces/{id}/study/progress, returning chapter and material rollups and the weak items, with recall computed in Go. Recommendation: yes. Without it the page is coverage and attempts only, which is what the Study tab already shows.
  6. Recall buckets. Solid at 0.9 and above, shaky 0.7 to 0.9, fading below 0.7, the target retention the server already uses. Words on item rows, counts and a bar per chapter, no percentages. Recommendation: as stated. Note that "fading" also names a review mode (blue, from Learning's Review tab); if that clash reads wrong, the third bucket becomes "weak".
  7. What counts as a weak item. Recall below 0.7, or the latest answer was a miss. Sort by recall, show at most 5, then "Review workspace", which starts today's whole-workspace review. Recommendation: as stated; a session made of exactly the weak items would be a new review group.
  8. Chapter grouping. A quiz or set counts under its tree chapter (chapter_id), the same grouping review suggestions use; its generation scope (scope_chapters) is ignored. Quiz scores stay on the quiz, never averaged per chapter. Recommendation: as stated.
  9. Actions on the page. Read-only apart from navigation and starting a review. Recommendation: no marking read, no stopping tracking, no quick review; the Study tab and the Files panel own those.
  10. Stopped items. Hidden from the chapter lists, with a "2 stopped tracking" count that opens Files. Recommendation: as stated.
  11. Time studied. Show per-session time only, from recorded review sessions, and no workspace total while attempts and reading have no duration. Recommendation: per-session only, labelled "review time".
  12. Progress off or empty. With progress off, one line explaining that quiz results are still kept and a link to Settings. With nothing tracked, the page falls back to the map placeholder and the three recording actions, as Learning's Progress does. Recommendation: as stated.
