1. Painted page frame in the app

The grey margin around the page becomes paint. The frame keeps today's gap (10 px on desktop, 6 px on phones), so nothing moves. While a frame is on, the cover behind the top bar's notch turns transparent, so the notch sits on the paint. The scenes are pre-rendered WebP images, 2 to 5 KB each (round 1 measured live SVG paint at about 10 times the raster work).

4. C3, mouse pointers: what it would take

What is sent today

  • A note's presence carries the peer's name, colour and caret or selection (Yjs relative positions that follow the text), at most one update per 50 ms. No mouse pointer is sent, so C3 needs new code end to end.
  • The collaboration server relays presence as opaque bytes in 30 ms batches, up to 64 KB per entry. Each user may send 200 messages a second; a pointer at 20 a second fits easily.
  • Viewers (view mode) send and receive no presence at all, so they would see no pointers either, nor carets today.
  • Office files get presence from the editor session's branch now (carets, selections, names). Pointers there would be extra work in each format.

Inside a file

Possible. A pointer is sent as the block under the mouse (blocks already have stable ids) plus an offset inside it, so it lands on the same words at any window width or zoom. It is drawn in a layer outside the editable, so it never re-renders the editor, and cleared when the mouse leaves the page. Touch screens have no pointer to send. Office needs one mapping per format: page coordinates for Word, slide coordinates for PowerPoint, cell and offset for Excel, in BetterOffice's overlays.

Outside the file, like side panels

Not as pointers. Each person's panels show different things: their own chats, their own panel widths and folded chapters, different screen sizes. A pointer position there has no shared meaning. Presence also lives per document today, so nobody knows what a peer's panels show. What can work is presence per item, for example small avatars on file-tree rows showing who has which file open. That needs a workspace-wide presence channel on the server, which does not exist yet; it would sit next to the editor session's avatar group work.

Suggestion: skip pointers in notes for now (the caret already shows where people are), and consider file-tree avatars as a separate follow-up.
