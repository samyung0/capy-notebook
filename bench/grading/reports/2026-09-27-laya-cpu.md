# Laya grading on the ingest VM, 27 September 2026

Laya runs on the ingest VM without a GPU, but its stock checkpoints fell well
short of Jev on the matched grading pilot. The developer stopped the wider
replay after these results and switched evaluation to Alibaba's decision model.
Application grading and ingest configuration are unchanged.

## Earlier Jev experiment and replay inputs

- [Jev findings, 19 September](2026-09-19-typesafe-jev-judge.md).
- [Original request builder](../scripts/typesafe_math.py).
- [Essay fixture](../fixtures/typesafe_rubric_cases.json) and the eight English
  [seed files](../fixtures/seeds/).
- [Worked math](../fixtures/typesafe_math_cases.json),
  [algebra](../fixtures/typesafe_algebra_cases.json),
  [units](../fixtures/typesafe_units_cases.json),
  [equivalence](../fixtures/typesafe_equiv_cases.json), and
  [routing](../fixtures/typesafe_route_cases.json) fixtures.
- Archived Jev responses are under `data/grading-benchmark/runs/typesafe-*.jsonl`.
  They are present on this developer PC and ignored by Git.

The old run used the hosted `jev-1.13.0` release through `jev-latest`.
It agreed with the expected award on 1,544/1,592 English seed answers,
97.0%, and 86/96 essays, 89.6%, at threshold 0.5. At 0.6 the seed agreement
was 97.9%. It accepted 17/35 incorrect worked math answers without a reference,
and 7/19 incorrect rational-expression rewrites. Textual rubric checking and
calculation checking were separate experiments, even for mathematics questions.

The replay reconstructs exactly the archived state and question definitions.
Each marking point is one `noul`, with no model answer. All points met earns
1, some earns 0.5, none earns 0. Per-point errors are also counted because
two different sets of met points can produce the same partial award.
Jev was not called again. This is a comparison with its archived release.

The preparation step reproduced the published Jev counts before writing
2,489 requests: 1,688 rubric answers, 183 worked-math conditions, 217 algebra
pairs, 235 unit pairs, 64 other equivalence pairs and 102 question-only routing
cases. Arguable labels are retained in raw output but excluded from scores.

Labels are AI-authored/reviewed synthetic examples, not independently graded
student submissions. All reported comparisons are in English. The multilingual
checkpoint's name does not make this a multilingual grading evaluation.

## Runtime and pilot

The official [Laya runtime](https://github.com/NandhaKishorM/laya/tree/4066d5d5fbf08b66c6757ddeedbd797bd7655bc0)
was pinned to `4066d5d5fbf08b66c6757ddeedbd797bd7655bc0`, version 0.3.20.
All three checkpoints came from the [official bundle](https://huggingface.co/convaiinnovations/laya/tree/55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851),
revision `55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851`. Downloaded-file SHA-256
hashes are in the local `models.manifest.json` artifact.

The host is `capy-ingest-1`, Debian 13.7, with 8 KVM vCPUs backed by an AMD
EPYC 9645, AVX-512 BF16 support, and 15,996 MiB usable RAM. It had about
13,427 MiB available before testing and 388 GiB free disk. Each test ran as
`capy-ingest` in an isolated transient systemd unit with `CPUQuota=200%`,
`CPUWeight=10`, `Nice=10`, `MemoryMax=4G` and `MemorySwapMax=0`.
Torch used two intra-op threads and one inter-op thread. Packages were
PyTorch 2.14.0+cpu, Transformers 5.17.0 and huggingface-hub 1.33.0, on Python
3.13.5. The complete package list is preserved with the run artifacts.

The pilot contains every essay and the first two seed question families in
each of eight domains: 96 essays and 63 seed answers after the original label
exclusions. Answer variants of a family stay together. Default `false`/`true`
labels and threshold 0.5 were used for this table.

| Checkpoint | Seed awards correct / 63 | Essay awards correct / 96 | Met essay points missed / 214 | Unmet essay points credited / 170 |
| --- | ---: | ---: | ---: | ---: |
| Archived Jev | 61, 96.8% | 86, 89.6% | 0 | 15 |
| Laya English | 41, 65.1% | 47, 49.0% | 13 | 107 |
| Laya multilingual | 42, 66.7% | 44, 45.8% | 106 | 37 |
| Laya typed-decisions | 34, 54.0% | 43, 44.8% | 5 | 130 |

All 477 pilot requests returned valid results. No state, marking-point
instruction or option text was truncated. English and typed-decisions mainly
over-credit; multilingual frequently misses points that are present. Raising
the threshold trades those error types rather than closing the gap.

The runtime documents a possible sensitivity to `false`/`true` label text, so
a second pilot changed only these labels to `B`/`A` on the same 63 seed
answers. At 0.5, English fell to 28/63, multilingual to 40/63, and
typed-decisions to 28/63. These were additional completed runs, with no
failures. This variant was rejected. No marking instruction was rewritten and
no checkpoint was fine-tuned.

The interrupted wider replay used multilingual with the original labels and a primary
threshold of 0.5. It had the highest seed pilot agreement, 42/63 versus
English's 41/63, and the lowest measured CPU cost. That one-answer lead is
not evidence that it is generally more accurate than English. The developer
stopped this run after 419 completed requests: the 96 essays and 323 seed
answers. Seed agreement at that point was 209/323, 64.7%. This ordered prefix
is not the complete seed corpus or a representative held-out score. The
remaining 2,070 requests, including all math/equivalence/routing probes, were
not run. Its artifact has no completion record and the scorer marks it
incomplete. No further Laya inference was performed after the stop request.

## CPU and memory measurements

These are warmed SDK calls, one answer at a time, excluding HTTP overhead and
queueing. Two-point seed answers and four-point essays have different costs.
Weights were downloaded before timing. Load times are process-cold but include
whatever filesystem cache the host had, not guaranteed disk-cold startup.

| BF16 CPU checkpoint | Files on disk | Peak process RSS | Peak unit memory | Seed p50 / p95 | Essay p50 / p95 | Load / first inference |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| English | 807 MiB | 3.29 GiB | 3.21 GiB | 0.490 / 0.605 s | 1.275 / 1.776 s | 2.56 / 1.80 s |
| Multilingual | 647 MiB | 2.34 GiB | 2.98 GiB | 0.187 / 0.216 s | 0.501 / 0.718 s | 6.76 / 0.76 s |
| Typed-decisions | 807 MiB | 3.34 GiB | 4.00 GiB | 0.464 / 0.569 s | 1.271 / 1.777 s | 3.89 / 1.81 s |

RSS and unit memory are different measurements. Unit memory includes charged
filesystem cache; RSS can include shared or file-backed pages. Typed-decisions
reached the 4 GiB cap and recorded 126 `memory.max` events, requiring reclaim,
but no OOM or OOM kill. All three pilots reported zero process swap.

The runtime holds parameters in FP32 even when using BF16 autocast for
computation. English/typed have 421,293,827 parameters and multilingual has
321,908,995. The CPU-only Python environment adds about 975 MiB on disk.

An initial FP32 English run was stopped after 14 completed essay answers to
test BF16. On those same 14 answers, median time fell from 3.713 to 1.296 s,
about 2.9 times faster. The largest probability movement was 0.011, and none
of the 56 point decisions crossed 0.5. This small precision comparison does
not establish parity on the full corpus. The interrupted file is preserved
and is not counted as a completed accuracy run.

## Deployment constraints

The test establishes that one CPU process can run within a 2-vCPU, 4-GiB
budget on this host. It does not establish a minimum memory requirement or
capacity under simultaneous parser load. A production HTTP server would add
request queueing and serving overhead to the SDK timings.

The live nonprod parser permits 6 GiB, the library database 3 GiB, the UAT
ingest worker 1 GiB, and the coordinator and import worker 384 MiB each.
Those limits plus a 4-GiB model sum to 14.75 GiB, leaving under 1 GiB of the
host's usable RAM for the OS, Docker, sampler and other processes if every
component reaches its limit. Additional local or production lanes increase
that demand. The documented production parser budget alone is 14 GiB.
Idle free memory therefore cannot justify an unconditional deployment on the
shared host.

The benchmark used no GPU, changed no application service, opened no endpoint,
and sent no requests to the hosted Jev API. It used only the synthetic grading
fixtures. At the developer's request, the complete isolated directory
`/opt/capy-laya-bench-20260927`, including all model weights and the runtime,
was removed at 03:00 UTC on September 27. All 20 result/log files were copied
to the developer PC and verified against remote SHA-256 hashes before removal.
No Laya unit was running, and available VM RAM returned to about 13.1 GiB.

## Reproduction and artifacts

The runner is [laya_cpu.py](../scripts/laya_cpu.py). Preparation and reporting
use the standard library; inference needs Linux and the pinned SDK. Python
3.11 or newer is required. From the repository root, after installing the
pinned Laya source and the package versions above in a separate CPU environment:

```sh
python bench/grading/scripts/laya_cpu.py prepare --baseline data/grading-benchmark/runs --output data/grading-benchmark/laya-20260927/requests.jsonl
python bench/grading/scripts/laya_cpu.py download --output data/grading-benchmark/laya-20260927/models --revision 55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851
python bench/grading/scripts/laya_cpu.py run --dataset data/grading-benchmark/laya-20260927/requests.jsonl --output data/grading-benchmark/laya-20260927/multilingual-full-reproduction.jsonl --checkpoint data/grading-benchmark/laya-20260927/models/multilingual --model multilingual --revision 55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851 --threads 2 --dtype bf16
python bench/grading/scripts/laya_cpu.py report --dataset data/grading-benchmark/laya-20260927/requests.jsonl data/grading-benchmark/laya-20260927/multilingual-full-reproduction.jsonl
```

Use a fresh output path for another run. To reproduce the pilots, add
`--suite rubric --pilot` and choose `models`, `models/multilingual` or
`models/typed-decisions`. The label probe used the pilot's 63 seed rows,
preserved as `requests-pilot-seed.jsonl`, with `--opaque-labels`.

The developer-PC artifacts are under ignored
`data/grading-benchmark/laya-20260927/`: request data and source hashes,
model-file hashes, package versions, per-request probabilities and timings,
completion records, summaries and VM observations. Each run records its
dataset hash, executed runner hash, explicit checkpoint revision, precision,
threads and planned request count. The original runner used for the first
pilots is preserved as `runner-original.py`; subsequent runs record the
version that adds the explicit label experiment.

Validation: the preparation check reproduced both archived Jev rubric totals;
the two [scoring tests](../scripts/test_laya_cpu.py) and seven existing grading
runner tests passed. Ruff formatting and checks passed for the new Python
files. No frontend or pipeline runtime was edited.
