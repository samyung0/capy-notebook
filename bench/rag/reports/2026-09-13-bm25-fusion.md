# BM25 and calibrated score fusion on frozen retrieval inputs

BM25 improved lexical retrieval, but it did not solve the original numbered-section
lookup. On the retained multilingual held-out questions, lexical hits rose from
225/312 to 241/312. Development-calibrated BM25/dense fusion reached 308/312
hits and nDCG@5 0.8687, compared with current hybrid's 304/312 and 0.8267.
Dense-only still found one more labeled answer, with nDCG 0.8595.

The calibrated fusion missed all four JLPT locator variants. Keeping the current
all-term rules while substituting BM25 preserved the existing JLPT results and
improved multilingual hits to 308/312, with nDCG 0.8439. This supports testing
BM25 alongside document-aware chunking; it does not support replacing the
existing lookup behavior with one global score mixture. No runtime change or
model call was made.

## Protocol fixed before new scores

The user authorized further retrieval experiments while deferring reranker
adoption. This benchmark compares lexical scoring and score fusion, leaving
chunk boundaries, indexed text, language detection, vectors and application
settings unchanged. It makes no model calls. The 624 multilingual questions
and five JLPT diagnostics are reused from the September 13 frozen experiments.
Both retained development and held-out partitions have been inspected before;
this is a controlled comparison, not fresh unseen validation.

Rebuild only a disposable PostgreSQL 16 lab index from the retained exact text.
Use the production CJK bigram tokenizer and per-chunk PostgreSQL language
configuration for both document and query analysis. Retain every scoped chunk's
actual cover-density score, match flags, query lexemes and dense cosine score,
including candidates absent from either top-40 list. Do not impute zero merely
because a candidate was outside a prior lexical list. References retain their
empty lexical representation. The lexical statistics use each query's full
assigned document-locale scope; JLPT uses its original three-file scope.

BM25 uses positive Robertson/Lucene IDF
`log(1 + (N - df + 0.5) / (df + 0.5))`, multiplied by
`tf * (k1 + 1) / (tf + k1 * (1 - b + b * length / average_length))`, summed once
per distinct normalized query lexeme. Documents use the exact PostgreSQL
lexemes, with frequencies from its analyzer and post-analysis token counts for
length. Query lexemes are normalized exactly once using each chunk's existing
configuration; no generated lexeme is fed through a stemmer again. Statistics
are over all nonempty lexical documents in the query scope. This is an exact
BM25 formula over the existing analyzer, not a claim of byte-identical Lucene
scoring or Elasticsearch length-norm encoding. Formula/defaults follow the
[Lucene BM25 documentation](https://lucene.apache.org/core/9_12_2/core/org/apache/lucene/search/similarities/BM25Similarity.html);
PostgreSQL's [ranking documentation](https://www.postgresql.org/docs/16/textsearch-controls.html)
describes cover density and its lack of collection-wide relevance statistics.

Compare these fixed references and ablations:

- Dense-only, current lexical ordering alone, raw `ts_rank_cd` alone, and current
  hybrid RRF, reproduced against the retained output lists.
- Standard BM25 alone (`k1=1.2`, `b=0.75`), plus one global development-selected
  BM25 setting from `k1 ∈ {0.6, 1.2, 2.0}`, `b ∈ {0, 0.5, 0.75, 1}`.
- BM25 score order fused by ordinary RRF with lexical weights 0.5 and 1, k=60.
- A scorer-only replacement control retains PostgreSQL match eligibility,
  all-term priority and the current short-query full-weight exception, while
  replacing cover-density ordering with BM25. This isolates scoring from the
  existing query heuristics.
- Convex score fusion for raw cover-density and development-selected BM25:
  `alpha * normalized_lexical + (1-alpha) * normalized_cosine`. Normalize each
  actual score over the method's dense40/lexical40 union using min-max; a constant
  channel becomes zero. Select one global alpha per lexical scorer from
  `{0, 0.1, …, 1}` on development. Also report the fixed alpha=0.5 reference.
  This calibrates a mixing coefficient, not a probability of relevance. The
  [fusion study by Bruch, Gai and Ingber](https://arxiv.org/abs/2210.11934)
  motivates a direct calibrated-score comparison rather than assuming ranks
  discard no useful information.

Select the BM25 parameters by mean development nDCG@5 across locale/task cells,
weighting populated cells equally. Break metric ties toward the standard
parameters, then earlier listed settings. Freeze that selection before tuning
fusion, then select each alpha by the same objective, breaking ties toward
smaller lexical weight. Do not tune by language, task phrase or held-out result.
Publish every grid outcome and all fixed/selected arms, including regressions.

Use forty candidates per leg, top forty after fusion, the existing four-per-file
cap with overflow, and final top five. Report lexical Recall@40, candidate-union
recall, fused Recall@40, Hit/Recall/nDCG/MRR@5 and relevant target ranks. Keep
MIRACL and controlled cohorts separate, with locale/task breakdowns and JLPT
listed individually. Source-level labels and actual result positions retain
the prior metric definition. No source labels change after inspecting outcomes.

Before outcomes, verify BM25 against a hand-computable fixture and PostgreSQL's
lexeme frequencies against independently expanded `ts_debug` analyzer output.
Freeze input, runner and protocol hashes. Reproduce the current baseline and
investigate any mismatch before comparing quality. Inspect all held-out hit
losses of the selected BM25 fusion if few, otherwise the largest ten, and an
outcome-independent bounded sample of gains. Preserve exact source packets and
flag plausible unjudged MIRACL alternatives. Report source-family uncertainty
and the limited traditional-Chinese controlled coverage. No method from this
experiment is adopted into the runtime.

## Execution and baseline verification

The run reused the [multilingual corpus and vectors](2026-09-13-multilingual-language-handling.md)
and [JLPT diagnostic](2026-09-13-jlpt-lookup.md): 3,277 multilingual chunks plus
223 chunks in the original three-file JLPT scope. The 624 multilingual questions
retain their original 312/312 partition. Each split contains 120 MIRACL and 192
controlled questions. Taiwan/Hong Kong have controlled sources only. Queries
search their assigned source-language scope; this is not a mixed-language or
complete MIRACL evaluation.

The embedding pin remains DeepInfra Qwen/Qwen3-Embedding-4B v1, 2,560 dimensions,
with the existing query instruction and six-significant-digit/half precision
serialization. Existing vectors were reused; ranking uses exact cosine, not
ANN. Indexed text, stale headings, language detection and empty reference
lexical vectors were preserved. All 223 JLPT indexed texts were checked against
a fresh read-only snapshot before the run.

A disposable PostgreSQL 16 database provided the actual `to_tsvector`,
`websearch_to_tsquery`, `ts_rank_cd` and language configurations. Every one of
3,500 document term-frequency histograms matched independently expanded
`ts_debug` output. Thus the BM25 inputs use real stemmed/stopword-filtered
PostgreSQL lexemes and existing CJK bigrams, not a whitespace approximation.
The independently checked hand fixture verifies positive IDF, saturation and
length normalization. Queries are analyzed once per existing chunk language;
there is no second stemming pass.

The first baseline gate found five list differences before any BM25 selection:
one Japanese MIRACL fifth hit and four JLPT neighbor-order differences. The
legacy SQL sorts tied IDs under `en_US.utf8`, whereas Python sorts Unicode code
points. The production JLPT SQL also has no explicit final lexical tie key.
A recorded pre-outcome amendment uses native PostgreSQL collation for current
baseline ties and retained historical JLPT ranks only within equal eligibility,
all-term and cover-density groups. BM25/raw-score arms retain their fixed ID
tie rule. Original code, freezes, features and the failed audit remain intact.

The amended baseline reproduced all 629 prior output lists exactly. The tie
correction changed no labeled target rank, Hit, Recall, nDCG or MRR in the five
affected cases. It changed only other passages' order or membership. The current
SQL's unspecified tie order remains a reproducibility limitation; this benchmark
did not change the runtime to resolve it.

All 283,731 scoped query/document pairs have actual cover-density and dense
scores. There were 5,009 positive PG scores on dense candidates outside the
current lexical top forty. Those values are retained for score fusion rather
than replaced with zero. No positive PG score belonged to a nonmatching
`tsquery` document. Full selected-BM25 scores are also saved for every pair.
The run produced 27,676 result records across the frozen arms and grid settings.

Development selected `k1=2.0, b=0.5`; its cell-balanced lexical nDCG was 0.5852
versus 0.5829 for the standard `1.2/0.75` setting. Both PG and BM25 convex fusion
selected lexical alpha 0.2. Their development objectives were 0.9281 and 0.9323,
respectively, versus 0.9187 for alpha zero. Selection hashes were checked before
held-out scoring. These small differences do not establish universal optimal
parameters, and no locale or held-out result was used for selection.

## JLPT locator behavior

Target ranks below refer to the ranked list before final selection. Ranks above
five are misses. All candidate pools contain the target, so these failures are
ordering failures rather than missing-candidate failures.

| Query | Current hybrid | Dense | Selected BM25 alone | BM25 with current hybrid rules | Calibrated PG fusion | Calibrated BM25 fusion |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `question 10 reading comprehension passage N1` | 12 | 24 | 19 | 12 | 20 | 17 |
| `問題10 次の文章を読んで 読解` | 8 | 16 | 9 | 8 | 9 | 9 |
| `問題 10 次の文章を読んで` | 1 | 13 | 9 | 1 | 8 | 8 |
| `問題 10` | 2 | 19 | 8 | 2 | 17 | 14 |
| Subject question about cyanobacteria and environmental change | 1 | 1 | 1 | 1 | 1 | 1 |

The term-level review of the second query shows why ordinary BM25 is insufficient
here. Its first result is the bare Question 7 instruction, only 44 analyzed
lexemes long, with score 27.48. The correct Question 10 passage contains 376
lexemes and scores 14.76, rank nine. It carries the stale previous-question
heading, preceding answer options and passage text. Eight overlapping instruction
bigrams collectively outweigh the correct passage's distinctive `10` contribution
of 1.99, while length normalization favors the short instruction. The scope has
219 nonempty lexical documents with mean analyzed length 113.99.

The correct target is the only all-term match. That existing ordering rule makes
it lexical rank one even though ordinary BM25 ranks it ninth. The subsequent
current fusion still misses the second query because the longer typed query
receives only half lexical weight. Removing the all-term rules during calibrated
fusion also loses the third and fourth locators that current hybrid finds.

This is measured interaction between tokenization, length normalization, current
chunk packing and lookup semantics. It does not establish an embedding-model
defect, and it does not justify a special rule for this phrase. A document-aware
representation should distinguish an instruction-only fragment from its related
passage and preserve the numbered-section relationship. The existing structural
problem needs attention alongside lexical scoring.

## Source review and uncertainty

Selected BM25 convex fusion gains five held-out hits and loses one against
current hybrid. All six changes were inspected against exact retained source
text. Labels stayed unchanged. It also has 61 nDCG improvements and 20 declines;
the other ordering changes were not individually adjudicated.

Three gains are controlled cross-language queries. The Spanish and French
seminar-enrollment questions now return the correct small red container record,
with the fictional 51-minute answer, first. The French backup question recovers
the correct 72-minute record at position four. Its first result describes the
same task for a large red container, so recovered coverage does not imply perfect
ordering or a correct generated answer.

The two natural-source gains require label caution. The French Mediterranean
question recovers its labeled scientific-commission membership list at position
five, but that passage explicitly includes non-coastal countries. The French
axiom question recovers its labeled Euclid-postulate passage at position three,
behind broader definitions; “most important” is underspecified. Neither metric
gain proves that a complete answer would improve.

The single lost hit is the English US gastrointestinal-disorder question. Its
labeled broad disease passage moves from fourth out of the top five. The returned
passages discuss common functional disorders and prevalence, but none explicitly
resolves the US-qualified question. The gold also has imperfect scope alignment.
The loss is real under the retained labels; it does not prove that every promoted
passage is irrelevant. No external medical claim or generated answer was evaluated.

A source-family bootstrap uses 2,000 draws, seed 20260913. For natural questions,
selected BM25 fusion's nDCG difference from current hybrid is +0.0656, with a
95% percentile interval [0.0335, 0.0985]. Against dense it is -0.0018, interval
[-0.0224, 0.0177]. Natural questions span 119 held-out source families. Controlled
questions have only four families after keeping translations and variants
together: the difference is +0.0273 [0.0129, 0.0417] against current and +0.0162
[0.0091, 0.0260] against dense. Those few authored families are a weak basis for
predicting real-material behavior despite the positive intervals. There is no
multiple-comparison correction, and both retained splits were previously inspected.

## Runtime implications

BM25 is worth evaluating as the lexical scorer when document-aware chunks are
ready. The scorer-only replacement with existing hybrid rules improves this
retained multilingual set without a held-out hit loss or a JLPT regression.
However, it leaves the original failed locators unresolved, and some gains rely
on incomplete public judgments. This is a candidate implementation direction,
not an adopted production change.

The global 20% lexical mixture should not be installed from these results. It
wins the frozen development objective and improves overall held-out ordering,
but removes useful lookup behavior and has no natural-source advantage over
dense-only. Language-level analysis remains appropriate; language alone does not
separate a semantic question from a numbered-section locator. Preserve that
distinction through document structure or general lookup handling, not a list
of special query phrases.

A deployed BM25 implementation also needs an explicit corpus-statistics policy.
This experiment computes IDF and average length over the full assigned query
scope, including all retained source documents in that locale, while excluding
empty lexical records. A typical engine uses index-wide statistics even when
search results are filtered. Its numbers would therefore differ in a shared
multi-workspace index. Engine choice, filter behavior, analyzer parity, update
cost and retrieval latency require separate validation. No extension, database
upgrade, registry entry or global weight change was made here.
