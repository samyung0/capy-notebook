### Suggested approach

1. **Fix the playground's `inspect_document` first.** Every growing note fails to append (183
   failed calls), so the agent writes "Part 2" notes or rewrites whole notes, which confounds any
   materials-quality comparison. A stub serving the run's own materials (and earlier turns', as the
   question stubs now do) is enough. Same for `read_document` (6 of 17 ok).
2. **Map the flow with costs and catches.** For each step (library rules in the system prompt and
   skills, browse, search with roles/topics, read, capture, figures, bank tools), record its prompt
   tokens (tool schema + rule text, `scratchpad`-style measure: chars/4 of `chat.system_prompt`,
   `skills.SKILLS[...].text(True)`, `contract.model_schema(n)`), its calls and refusals per run, and
   what it catches (from run records). Keep it to a one-page table.
3. **Candidate simplifications to test** (each as a playground config or flag, one change per arm):
   - Topic filter: guessed ids cause most search refusals. Options: drop `topics` (query + roles
     only), or map an unknown topic id to the closest real one instead of refusing.
   - Roles filter: sent on every search; test whether dropping it changes what is read (locator
     on-topic rate) or only costs tokens.
   - browse_knowledge: 11 calls in 99 runs; test folding the subject catalog into search results or
     the library rules.
   - Question bank tools: never copied from; either the prompt path to them needs fixing or they
     come out of the default tool set (token saving on every call). Needs the bank running locally.
   - Search result cards: measure the head lines (`roles`, `topics`, `teaches`, `scope`) per card in
     tokens and test a shorter card.
   - The section-reading arguments (contract v17 removal) as part of the same cleanup.
4. **Compare with the bench.** `bench/rag/intake/scripts/run_requests.py --config <name> --once
   --only ...` against a playground per arm (launch entries in `.claude/launch.json`; the leniency
   worktree's is `rag-playground-lenient-18794`), 16 requests per arm as in the 2026-10-13
   measurement, then refusals/tokens/materials from the run records and, for quality, the judges in
   `bench/rag/intake/scripts/materials_judge.py` (fidelity, pairwise; `--pack` for subagent
   judging; it still reads `run["ledger"]`, which newer runs lack, so patch that read first). Decks
   were off in every comparison so far; add deck requests if decks are in scope.
