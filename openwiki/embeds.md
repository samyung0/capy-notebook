# Embeds and the element catalog

A material document (a note, quiz, flashcard set, mindmap or diagram) is a list
of Plate elements. Most are ordinary text blocks; the rich ones (charts,
plots, graphs, interactive HTML, Mermaid diagrams, embedded quizzes and
flashcard sets) are **embeds**, and each has a different name in every layer
that handles it. The **embed catalog** lists all of it in one place:
`server/internal/embeds` (Go), generated by `pnpm gen:openapi` into

| File | For |
| --- | --- |
| `pipeline/pipeline/generated/embeds.json` | the pipeline (package data) |
| `src/api/embeds.generated.ts` | the browser (`EMBED_CATALOG`, typed by its literal values) |
| `collaboration-rs/crates/notes/src/catalog.rs` | the collaboration server (`notes::catalog`) |

`TestGeneratedFilesAreCurrent` fails when one is stale. Every layer keeps its
own validators and renderers and is **tested against** the catalog: a test in
each language compares its hand-written lists with it (the work split and the
lists to cover are in `todo-embeds.md`). Decisions: `human/frontend/plate-editor.md`
(Epo 2026-10-13).

## What it holds

- **`elements`**: every element type a stored document or a room may hold,
  including Plate's transient ones (a media `placeholder` while it uploads,
  `mention_input` and `slash_input` while typing). For each: `void`,
  `inline`, `topLevel` (only a top-level block), `required` keys besides
  `type` and `children`, `fields` (the closed key set, when there is one),
  `forbidden` keys, `sharedText` keys (held as a Y.Text so typing merges;
  only `mermaid.source`), `assets` (paths naming editor assets, `[]` walking a
  list), `resizable` (a width of `MEDIA_WIDTH_MIN`–`MEDIA_WIDTH_MAX` %),
  fixed `children`, and the `materials` kinds whose documents may hold it.
  A type the catalog does not list is refused by every layer: a stored
  document holding one stays readable with an "unsupported block" placeholder,
  and editing it is refused until it is fixed (Epo 2026-10-13; enforcement
  lands with each layer's tests).
- **`embeds`**: the rich kinds, with their name per layer, storage class,
  where they render (`surfaces`) and who edits them (`edit.user` surfaces,
  `edit.agent` tools):

  | Kind | Class | Element | Fence | Chat | Material kinds |
  | --- | --- | --- | --- | --- | --- |
  | chart | value | `chart` | ```` ```chart ```` JSON | `Chart` | – |
  | plot | value | `plot` | ```` ```plot ```` JSON | `Plot` | – |
  | graph | value | `graph` | ```` ```graph ```` JSON | – | – |
  | html_embed | value | `html_embed` | ```` ```html-embed ```` YAML | `Interactive` | – |
  | mermaid | live_source | `mermaid` | ```` ```mermaid ```` source | `Diagram` | mindmap, diagram |
  | quiz | item | `material_ref` | ```` ```quiz ```` YAML | – | quiz |
  | flashcards | item | `material_ref` | ```` ```flashcards ```` YAML | – | flashcards |

  A **value** is an attribute of its node, replaced whole. A **live source**
  keeps its source in shared text. An **item** is a child material row with
  its own rooms, which a note references through `material_ref` with
  `refKind` set to the kind; Go owns its access, trash, clone, share, assets
  and quota. Chart, plot and graph are question blocks too
  (`questionBlock`); chart and plot are what `add_question_media` writes
  (`questionMedia`), and their `schema` is the JSON Schema the agent
  contract's `mediaBlocks` carries. Chat's `Diagram` and `Interactive` become
  `Mermaid` and `HtmlEmbed` with the rename (one word per kind in each layer's
  casing).
- **`materialKinds`**: each kind's required element (`quiz`, `flashcards`,
  `mermaid` for mindmap and diagram, none for a note) and whether it is an
  item (quiz, flashcards).
- **`limits`**: `HTML_EMBED_MAX_BYTES`, `HTML_EMBED_MAX_COUNT`,
  `MEDIA_WIDTH_MIN`/`MAX`, `CARD_FRONT_MAX`/`CARD_BACK_MAX` and the question
  bounds (`fieldlimits.QuestionBounds`). The Rust file declares each as a
  constant (`QUESTION_IMAGE_DIMENSION_MAX` and `QUESTION_MARKS_MAX` as `f64`).

## Adding an element or an embed kind

1. Add it to `Elements()` or `Embeds()` in `server/internal/embeds/embeds.go`
   and run `pnpm gen:openapi`. `TestCatalogIsConsistent` checks that every
   name it uses points at something listed (children, material kinds, the
   element holding an embed, agent tools).
2. Each layer's catalog test then names what is missing there: the Go and
   Rust validators, room admission, the editor and static plugins, the
   markdown rules, chat's components and the agent text.
