# Embeds: catalog, drift and open work

From the 2026-10-13 survey of how rich blocks (quiz, flashcards, mermaid,
chart, plot, graph, html-embed) move between chat, notes, standalone
materials, the collaboration server and agent prompts. Nothing below is
decided except where marked; current behaviour lives in
`openwiki/frontend/plate-editor.md`, `openwiki/question-bank.md` and
`openwiki/agentic-retrieval.md`.

Landed with this file: a live quiz room keeps plot blocks (they used to vanish
from the projection, so an agent's `add_question_media` plot never reached
learners; `plot.json` joins the shared question fixtures), the materials skill
no longer offers graph media (nor do the `contract.py` and `tools.py`
comments), and `/generate` no longer offers a chart `unit`.

## Where things stand

Each kind has a different name per layer, and the lifecycle code follows the
storage class rather than the kind:

| Kind | Plate node | Note fence | Chat (OpenUI) | Material kinds | Class |
| --- | --- | --- | --- | --- | --- |
| chart | `chart` | ```` ```chart ```` (JSON) | `Chart` | – | inline value |
| plot | `plot` | ```` ```plot ```` (JSON) | `Plot` | – | inline value |
| graph | `graph` | ```` ```graph ```` (JSON) | – | – | inline value |
| html-embed | `html_embed` | ```` ```html-embed ```` (YAML) | `Interactive` | – | inline value |
| mermaid | `mermaid` (+ caption) | ```` ```mermaid ```` (source) | `Diagram` | mindmap, diagram | live source (Y.Text) |
| quiz | `material_ref` (`refKind: quiz`) | ```` ```quiz ```` (YAML) | – | quiz | item reference |
| flashcards | `material_ref` (`refKind: flashcards`) | ```` ```flashcards ```` (YAML) | – | flashcards | item reference |

- **Inline value**: an attribute on the node, replaced whole; no row, no room
  of its own.
- **Live source**: a Y.Text `source`, so concurrent typing merges.
- **Item reference**: a child material row with its own rooms; Go owns access,
  trash, clone, share, assets and quota for it.

Chart, plot and graph are also question blocks (one schema for quizzes, notes
and chat). Plot has no editor anywhere (Epo 2026-10-13: not now): agents write
it, the question dialog and notes show it view-only, and users can remove it.

The fence parser is already single: the collaboration server runs the editor's
own `markdownConvert.ts` in V8. Everything else repeats the kind list by hand:
about 35 lists in `src/`, 15 in `collaboration-rs`, 30 across Go and Python.
The chart/plot schema exists five times: zod (`questions/validation.ts`), Go
`ValidateBlock`, Rust `notes/src/questions.rs`, Python `_chart_problems`, and
the `mediaBlocks` JSON Schema in the agent contract.

## Proposal: an embed catalog checked by every layer

The agent tool catalog worked because a tool lives in one layer with one
schema. An embed crosses five layers whose code differs for good reasons
(chat streams partial programs, Plate needs void nodes and selection fixes,
share pages need islands), so the counterpart is a catalog each layer is
**tested against**, not one each layer runs from.

1. **`embeds.json`, generated by `pnpm gen:openapi` from Go** (next to
   `agenttools`, which already owns the agent contract and `mediaBlocks`; the
   same freshness test and version handshake). One entry per kind: its name in
   every layer (Plate type, fence language and body format, OpenUI component,
   material kinds), storage class, data schema (JSON Schema; `mediaBlocks`
   moves here), limits, asset fields, which surfaces render it, who edits it
   where (user editor per surface, agent commands), whether it is allowed in
   questions, and its agent-facing text. A TS copy is generated beside
   `src/api/limits.generated.ts`.
2. **Agent text from the catalog.** `Formats.note` and the OpenUI
   descriptions of `Chart`, `Plot`, `Diagram` and `Interactive` quote each
   kind's text, so the html-embed rules exist once (today
   `agenttools.go:463` and `chat/schema.ts:328`). Python kind lists
   (`questions.py` `_MEDIA`, the skills text) read the catalog.
3. **One set-equality test per language** comparing its hand-written lists
   with the catalog: TS (`CUSTOM_BLOCK_LANGS`, the markdown serialize rules,
   `staticPlugins`, `document.ts` `CUSTOM_TYPES`, chat's Diagram/Chart to fence
   mapping), Rust (`material.rs` `validate_node`, `limits.rs` `OWN_KEYS`, quiz
   `BLOCK_TYPES` against question media, `edit.rs` inspect), Go
   (`validateNode`, `ValidateKind`). These would have caught every drift item
   below, the plot-in-quiz gap included.
4. **Shared valid/invalid fixtures per kind** that zod, Go, Rust and Python
   must all agree on, extending `server/internal/questions/testdata` (already
   read by the Rust item tests and parity corpus). Validators are not generated
   from JSON Schema: their error messages are tuned for agents and users.
5. **Embed limits in the generated limits** (`HTML_EMBED_MAX_BYTES`/`COUNT`
   carry a "keep in sync" comment in `document.ts:107`), with a Rust output
   added (`notes/src/questions.rs` constants are hand-copied today).
6. **`openwiki/embeds.md`**: the table above plus the catalog's fields, listed
   in AGENTS.md's wiki table.

Not centralized: renderers and editors (they already share `Mermaid.tsx`,
`CategoryChart`/`PlotChart` and `HtmlEmbed.tsx`), lifecycle code (per storage
class, in Go), and no cross-language plugin registry or universal embed node.

**Order**: the drift list first, then the catalog with its tests (they surface
whatever drift is left), then the agent text.

**Open for Epo**: Go as the catalog's source; whether to unify names while
there is no legacy data (`html-embed` / `html_embed` / `Interactive`,
`Diagram` / `mermaid`, mindmap and diagram both being one mermaid node).

## Drift found 2026-10-13 (open)

- `src/features/notes/markdown.ts` has no serialize rule for `chart`, `plot`
  or `graph` although `customBlockCode` handles them; what Plate's serializer
  does with them (copy as markdown) is unchecked.
- `inspect_document` prints a chart's or graph's `block` but not a plot's
  (`collaboration-rs/crates/notes/src/edit.rs:1375`).
- Two media-type lists in Rust: `edit.rs:189` (8 types, adds `video`,
  `media_embed`, `youtube`, `excalidraw`) and `material.rs:24` (4).
- `src/features/workspace/chat/generated.ts:32` stubs a `ScatterChart` that no
  spec has.
- `RESIZABLE_TYPES` (`src/features/materials/document.ts:172`) lists
  `diagram` and `mindmap`, which are not node types.
- `materialKindLabel` (`src/features/materials/MaterialListCard.tsx:31`)
  labels mindmaps and diagrams "Note".
- `src/features/materials/blocks.ts` is a second quiz/flashcards fence codec:
  `quizMarkdown`/`flashcardsMarkdown` are unused, the parsers serve only
  `src/mocks/`.
- `markdownConvert.ts` `draft()` and `dialogContext.tsx`
  `embeddedDraftFromFence` turn a fence into a create request twice; both drop
  card images.
- `src/features/materials/MermaidBlockLabel.ts` is imported nowhere.
- The notes markdown corpus (`collaboration-rs/crates/notes/tests/corpus`) has
  no chart, plot or graph fence; it is a frozen Node oracle, so new cases go in
  by hand.
- The note format never mentions a ```` ```graph ```` fence while the
  converter accepts one (paste and export round trips); intended, but the
  catalog should say so.
- Chart kinds are listed four times in TS (`questions/types.ts`,
  `questions/validation.ts`, `chat/schema.ts`, `BlockEditor.tsx`) and
  `openui.py` keeps its own `_SKIPPED_PROPS`.
- `lab/playground/configs/explain-teach.json:27` holds a stale copy of the
  building skill (old quiz format, chart `unit`).
